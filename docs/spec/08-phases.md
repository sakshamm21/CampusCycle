# 08 · Build phases and tasks

The build runs in seven phases, one branch and one pull request each (01 §1). Every task has an id (`P<phase>-T<nn>`), the spec it implements, and acceptance checks. A task is done when 01 §14 holds. Tasks marked **Sak** are done by the owner; the build session prepares everything around them and waits only for that step.

## 1. How the build runs

- **Where:** on Sak's Windows PC, in a coding-agent session opened in the folder `C:\Users\Saksham\Desktop\AI\CampusCycle`. The first action of every session is to print the working directory and stop if it is not that folder (or its `app` subfolder).
- **Folder layout on the PC:**
  ```
  C:\Users\Saksham\Desktop\AI\CampusCycle\
    plan\        this plan pack (read-only during the build)
    app\         the git repository github.com/sakshamm21/CampusCycle (all code)
  ```
- **Backend:** there is no local database. Phases 0 to 2 ran against one hosted free-tier Supabase project, `campuscycle` (region `ap-south-1` Mumbai). From P3-T00 on there are two (01 §3.4): `campuscycle-dev` for the PC, CI and every test, and `campuscycle` as production, which is never reset. "Works locally" in any acceptance line means: the app runs on the PC (or the emulator) against this project.
- **Order:** P0 → P6, strictly. Within a phase, tasks run in id order unless marked "any order".
- **Pull requests:** at the end of each phase, open the PR `phase-N-…` → `main` listing every task id with ✓, wait for CI to be green, then merge (squash) and tell Sak in one line what is now working.
- **Secrets:** never printed, never pasted in chat, never committed. Values the build session generates go into the gitignored files `app\.env`, `app\apps\admin\.env.local`, `app\apps\mobile\.env.local` and into hosted secret stores via CLI. The OpenRouter key, the Supabase access token for CI and Sak's own email and password are typed by Sak.
- **Questions:** the spec answers every design question. If something is truly missing, choose the option most consistent with the nearest spec section, note it in the PR description under "Decisions made during the build", and continue.
